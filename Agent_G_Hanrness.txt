# Enterprise Retrieval-to-Execution Harness — Evidence-First Research Report

Stand: 17.09.2026 · Suchbudget dieser Session: 5 Suchläufe (Stream A, C, E direkt belegt; Streams B, D, F–J teilweise aus Vorwissen mit Kennzeichnung [KB] = knowledge-based, in dieser Session nicht neu verifiziert). Alle 2026-Preprints sind als [2026-PREPRINT] markiert.

1. Executive Research Conclusion
Kernbefund: Die Literatur 2025–2026 hat die im Kontext formulierte offene Stufe („?“) unabhängig voneinander identifiziert und mit demselben Begriff belegt: Compilation. GraSP formuliert das Problem exakt: 
3
Retrieval answers "what skills are relevant"; execution answers "do this step now". But no existing method answers the structural question in between: "how do these skills depend on each other, and what is the minimal, causally ordered plan?" Die Antwort dort ist 
3
a compilation stage that transforms a flat set of retrieved skills into a typed directed acyclic graph (DAG) where nodes are instantiated skill invocations and edges encode explicit precondition–effect dependencies (state, data, order).

Was gesichert ist (EMPIRICAL_RESULT, Preprint-Niveau):

Flat/semantic Retrieval hinterlässt ein Prerequisite Gap; strukturelle Retrieval (GoS, TGR, Graph RAG-Tool Fusion) reduziert es messbar.
Metadaten (Name/Description) reichen bei ~80K Skills für Routing nicht aus; der Skill-Body ist Routing-Signal.
Deterministische Policy-Enforcement auf Tool-Call-Ebene (Progent) ist ein wirksamer, aber nicht vollständiger Schutz; Dual-LLM-Architekturen (CaMeL) wurden bereits gebrochen.
Was NICHT gesichert ist (INSUFFICIENT_EVIDENCE):

Kein Paper vergleicht Architekturvarianten A–H kontrolliert gegeneinander.
Kein empirischer Nachweis, welche Contract-Felder Reliability kausal verbessern (ABLATION_EVIDENCE_MISSING).
Kein etablierter Standard für ein Retrieval→Execution-IR existiert; GraSP/SkillDAG/SkillOps sind Einzelsysteme.
Architektonische Konsequenz (DESIGN_RECOMMENDATION): Das „?“ ist ein Contract Resolver, der ein advisory Retrieval Bundle gegen (a) maschinenlesbare Skill Contracts, (b) aktuellen Run State, (c) Policy und (d) Tool-Capabilities zu einem versionierten, hashbaren Execution Manifest kompiliert. Retrieval-Edges tragen Confidence; Execution-Edges tragen Autorität — und beide dürfen nie dieselbe Datenstruktur sein.

6. Retrieval-Graph Findings (Stream A)
A1 – Hybrid Seeding + Graph Diffusion (EMPIRICAL_RESULT, [2026-PREPRINT/EMNLP'26]): GoS-Pipeline: 
2
hybrid semantic-lexical seeding, reverse-aware Personalized PageRank, and context-budgeted hydration. Die reverse-aware Komponente adressiert direkt das Prerequisite-Problem: 
2

A2 – Skalierung: Empirisch belegt 200→2K (GoS); 80K nur für nicht-graphbasiertes Retrieve+Rerank (SkillRouter). INSUFFICIENT_EVIDENCE für Graph-Retrieval bei 10K–100K. Offene Frage: PPR-Kosten und Edge-Rauschen bei O(10⁵) Knoten.

A3 – Dependency-Diskriminator statt LLM-Induktion (Alternative): TGR trainiert einen Klassifikator auf 300K Paaren — potenziell reproduzierbarer als LLM-Induktion, aber nur Tool-Level.

A4 – Konflikt-/Duplikat-Kanten (SkillDAG, [2026-PREPRINT]): 
9
skills depend on, conflict with, specialize, or duplicate one another, a structure invisible to both full enumeration and embedding similarity. → Retrieval-Graph braucht mindestens 4 Kantentypen: depends_on, conflicts_with, specializes, duplicates.

A5 – Same-Capability Ambiguity: SkillResolve-Bench [Pointer] adressiert das Problem mehrerer Skills für dieselbe Capability — relevant für Enterprise (mehrere Versionen/Anbieter). Diversity-aware Routing: 
12
multi-skill routing requires recovering complete skill sets.

A6 – MCP-Skala: SING [2026-PREPRINT] auf 
31
779 servers and 7,471 tools; Ergebnis: 
31
improving Global Recall@5 by up to 59.8% and downstream success rate by up to 28.9% while reducing full-corpus tool-schema exposure by 99.8%. Wichtiger methodischer Punkt: 
31

10. Authorization/Trust Architecture (Stream E)
Belegte Prinzipien:

Deterministische Policy auf Tool-Call-Ebene: Progent 
43
represents privilege as a security policy consisting of symbolic rules over tool names and arguments. These rules specify which tool calls are allowed for task completion and which unnecessary ones are blocked for security. Mit 
42
an SMT-based procedure to determine whether policy updates are expansions or narrowings.
Privilege-Escalation-Coverage-Lücke: SEAgent demonstriert Confused-Deputy-Angriffe, bei denen 
37
the poisoned content retrieved in the first step ... polluted the context of the anonymous Spoke, which then successfully invoked the privileged open_front_door tool without being flagged.
Description Poisoning: Motivation für TRUSTDESC (Beschreibungen aus Code generieren statt vertrauen) [Pointer].
Trust Gates (DESIGN_RECOMMENDATION):

Ingest Gate (Skill-Registrierung): Digest, Signatur, Description-vs-Code-Konsistenz.
Resolve Gate: Retrieval-Bundle darf nur Skills mit gültigem Contract binden.
Authorize Gate (vor Manifest-Freigabe): Policy-Engine prüft gesamtes Manifest (nicht nur Einzelcalls) — schließt Confused-Deputy-Ketten teilweise, da Datenherkunft pro Knoten bekannt.
Runtime Gate (pro Tool-Call): Progent-Stil, unabhängig vom Manifest (Defense in Depth).
Commit Gate: Postcondition + Approval für irreversible Effekte.
Regelprüfung: Discovery ≠ Permission — SUPPORTED (SING zeigt: 99.8% Reduktion der Exposure ist Retrieval, nicht Rechte). Planning ≠ Authorization — SUPPORTED (CaMeL-Bruch zeigt: Plan des privileged LLM war nicht immun). Model choice ≠ authorization — INFERENCE.

Grenze: Progents Initialpolicy wird per LLM generiert — d. h. der Policy-Generator ist selbst LLM-abhängig. Enterprise: Policies aus Preset/Contract ableiten, LLM darf nur narrowen.

13. Versioning/Reproducibility Model (Stream H)
Definitionen (PROPOSED_STANDARD, angelehnt an ACM-Artifact-Terminologie [KB]):

STRUCTURAL REPRODUCIBILITY: gleicher Snapshot (preset, contracts, policy, retrieval-graph version, state snapshot) → byte-identisches Manifest (graph_hash). Testbar deterministisch.
BEHAVIORAL REPRODUCIBILITY: gleiches Manifest → gleiche Postconditions erfüllt (nicht gleiche Trajektorie).
STATISTICAL REPRODUCIBILITY: pass^k / Erfolgsrate über n Runs innerhalb Konfidenzintervall [KB: τ-bench pass^k].
Versionierte Artefakte: skill, contract, retrieval graph (inkl. Konstruktions-Seed/Modell — GoS-Repo-Hinweis zur Konstruktionsvarianz), preset, tool schema, model id, evaluator, policy. INSUFFICIENT_EVIDENCE, ob Semantic Versioning für Skills sinnvoll ist; Content-Hash ist die sicherere Basis.

14. Graph Evolution Architecture (Stream I)
Offline-Konstruktion (GoS): reproduzierbar nur mit fixiertem LLM/Cache.
Runtime-Edge-Proposal (SkillDAG): 
9
a propose-then-commit protocol lets the agent register execution-backed edges so the graph accumulates structure across episodes. Positiv: Kanten sind ausführungsbelegt. Risiko: Selbstbestätigung (Agent nutzt A→B, weil Kante existiert; Kante wird bestätigt).
Library-Maintenance-Loop (SkillOps): getrennte Schleife.
Self-improving Libraries (SkillWeaver): Gewinne belegt (
25
relative success rate improvements of 31.8% and 39.8%), aber Verifier-Qualität ist die Achillesferse.
Edge-Level-Metriken (keine etablierte Definition): edge precision (Kante genutzt ∧ Postcondition erfüllt), edge recall (fehlende Kante ↔ DEPENDENCY_MISSING-Fehler), churn rate, confidence calibration. Empfehlung: Kanten-Confidence nur über kontrafaktische Evidenz erhöhen (Erfolg ohne Kante vs. mit), sonst Feedback-Loop.

24. Evaluation & Regression Framework
Retrieval: Recall@k, Full Coverage (Diversity-Routing), Dependency-Pair Co-Recovery (neu), Token-Budget-Effizienz.
Resolver: Manifest-Determinismus (Hash-Gleichheit über n Builds), Konflikt-Erkennungsrate, Bind-Fehler.
Authorization: Unauthorized-Action-Rate (AgentDojo-Stil [KB]), Policy-Violation-Rate, Confused-Deputy-Suite (SEAgent-Szenarien).
Execution: Node-Postcondition-Rate, Repair-Success, Retry-Amplification (neu).
Reproducibility: pass^k, Repeated-Run-Variance.
Evolution: Edge Precision/Recall (neu), Churn, Regression-Rate nach Graph-Release.
Regression Gate: Kein Graph-/Contract-Release ohne Nicht-Verschlechterung auf E2E + Security-Suite.

Falsifikations-Check (Quality Gate 1–17, Kurzfassung)
Retrieval ohne Graph? Ja, bis 80K für Single-Skill-Routing (SkillRouter); Graph nötig, wenn Dependency-Completeness entscheidend ist → Graph ist optional, Resolver nicht.
Reine State Machine statt DAG? Ja für Approval-lastige, sequentielle Domänen → DAG nur bei echtem Parallelismus.
IR wirklich nötig? Ohne IR keine Structural Reproducibility und keine manifest-weite Authorization → IR bleibt Kernel, aber minimal (§17-Felder).
Contracts zu komplex? 15 Felder minimal; Rest optional. Nachweis für Reliability-Gewinn einzelner Felder fehlt — bewusst als Engineering-Ableitung markiert.
Graph Evolution mehr Drift als Nutzen? Unbekannt → nur gated, außerhalb Kernel.
Planner statt Resolver? CaMeL-Bruch und GraSP-Motivation sprechen dagegen; Planner darf vorschlagen, Resolver bindet.
Kernel (invariant): Contract-Schema, Manifest-Schema, Lifecycle-SM, Failure-Klassen, Policy-Gate-Interface. Alles andere — Graph-Retrieval, DAG-Parallelismus, Evolution — ist complexity-gated Extension.
